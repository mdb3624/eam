**UTILITY ASSET & FIELD OPERATIONS PLATFORM**

**MVP Scope and Delivery Baseline**

September 2026

# 1. MVP Objective

The MVP should demonstrate the platform's core operational value through one complete, traceable asset-event-to-field-resolution workflow. The initial reference use case is an electrical asset, with the transformer workflow used as the primary example in the current requirements.

The MVP should focus on proving the core platform foundation and end-to-end operational flow before expanding into the broader capabilities shown in the target-state architecture.

# 2. MVP Scope

| **MVP Area** | **Included** | **MVP Boundary** |
|---|---|---|
| **Asset Management** | Yes | Canonical asset record, transformer asset, basic hierarchy, status and asset history |
| **GIS / Location** | Yes | Asset location, map display, asset search and location verification/freshness |
| **Integration** | Yes | One initial SCADA/IED/event source through the integration gateway |
| **Event Processing** | Yes | Receive, retain, normalize and validate the selected source event |
| **Asset Identity** | Yes | Map source-system asset ID to the platform's canonical Asset ID |
| **Data Quality / Lineage** | Yes | Source, timestamp, validation/status and basic traceability |
| **Alarm Management** | Yes | Alarm creation, severity, acknowledgement and closure |
| **Incident Management** | Yes | Incident creation, status, linkage to asset/alarm/work order and timeline |
| **Outage** | Limited | Basic outage/impact context where reliable data is available; not full OMS replacement |
| **Work Management** | Yes | Create, assign, track and complete the work order |
| **Dispatch** | Yes | Basic crew availability, qualification and assignment |
| **Field Mobile** | Yes | Assigned work, asset/location, safety, inspection, photos/readings and completion |
| **Offline Field** | Limited | Essential assigned-work caching and synchronization, if included in release |
| **Notifications** | Limited | Critical operational notifications |
| **Inventory / Parts** | Limited | Record/request parts used; defer full inventory/procurement |
| **Audit** | Yes | Operationally significant user/system actions |

# 3. MVP End-to-End Workflow

The MVP should be demonstrated using the following single operational path:

| **Step** | **Activity** | **MVP Behavior** |
|---|---|---|
| **1** | Event detected | An abnormal transformer/electrical asset event is generated by the selected source. |
| **2** | Event received | The Integration Gateway receives the event and retains the original source payload. |
| **3** | Asset identified | The source asset identifier is mapped to the canonical Asset ID. |
| **4** | Asset located | The platform retrieves the asset's verified/last-known GIS location and displays it on the map. |
| **5** | Alarm created | The event is classified and an alarm is created using configured severity rules. |
| **6** | Incident created | An incident is created and linked to the asset and alarm when business rules are met. |
| **7** | Work order created | An emergency/corrective work order is created or entered by an authorized user. |
| **8** | Crew assigned | The dispatcher assigns an appropriately qualified and available crew. |
| **9** | Field work performed | The technician receives the work package, completes safety steps, inspects/repairs the asset and captures evidence. |
| **10** | Restoration recorded | The technician records completion/restoration information. |
| **11** | Work closed | The configured workflow closes the work order and incident. |
| **12** | Asset history updated | The event, incident, work and inspection evidence are retained in the asset history. |

# 4. MVP Functional Capabilities

## A. Platform Foundation
- User login and role-based access
- Canonical Asset ID
- Transformer asset record and basic hierarchy
- Asset status and basic lifecycle history
- API foundation
- Audit trail

## B. Integration and Data
- One initial external event source
- Integration adapter/gateway
- Original/raw event retention
- Canonical/normalized event
- Source message ID and timestamps
- Retry/error handling
- Basic integration health visibility

## C. Asset Identity and Data Quality
- External ID-to-canonical Asset ID mapping
- Duplicate/conflict detection for the MVP scenario
- Basic data-quality status
- Source and transformation traceability

## D. GIS and Asset Context
- Asset map
- Asset location and coordinates
- Asset search
- Location verification/freshness
- Basic nearby/network context

## E. Alarm and Incident
- Event classification
- Alarm creation and severity
- Alarm acknowledgement/closure
- Incident creation and tracking
- Incident timeline
- Asset/alarm/incident linkage

## F. Work and Dispatch
- Work-order creation
- Priority and required skill
- Work-order status
- Basic dispatch board
- Crew availability and qualification
- Crew assignment/reassignment

## G. Field Operations
- Technician login
- Assigned work list
- Asset and location information
- Safety checklist/acknowledgement
- Inspection/checklist
- Readings, notes and photographs
- Work completion and restoration
- Basic offline execution if included

## H. Closure and Traceability
- Incident/work-order closure
- Asset history update
- End-to-end event-to-resolution traceability
- Audit of significant actions

# 5. Deferred from MVP

The following capabilities should remain outside the MVP unless a specific business decision brings them into scope:
- Predictive maintenance and AI recommendations
- Advanced asset health/risk analytics
- Full inventory, warehouse and replenishment management
- Procurement and supplier workflows
- Advanced outage-management capabilities and full OMS replacement
- Advanced crew optimization/intelligent dispatch
- Broad weather/IoT/smart-meter/ERP/HR integrations
- Large-scale multi-utility and multi-region capabilities
- Advanced analytics and enterprise reporting
- Autonomous control of breakers or other safety-critical equipment
- Replacement of certified protection, SCADA or control systems
- Customer billing and full financial ERP replacement

# 6. MVP Acceptance Criteria
- A selected source event can be received successfully.
- The original source event is retained and traceable.
- The affected asset is identified through the configured identity mapping.
- The asset can be located and displayed in GIS.
- The appropriate alarm is created with the expected severity.
- The incident is created and linked to the asset and alarm.
- A work order can be created from the incident.
- A dispatcher can assign an appropriate crew.
- The technician receives the assigned work on the mobile application.
- Required safety and inspection information can be captured.
- Photos/readings/notes can be retained as completion evidence.
- The work can be completed and the incident/work order closed.
- The asset history reflects the completed operational event and work.
- The end-to-end transaction is auditable.
- Integration failures are visible and do not result in a false normal condition.

# 7. Recommended MVP Delivery Sequence

| **Release** | **Primary Scope** | **Exit Point** |
|---|---|---|
| **MVP 1 — Foundation** | Users/roles, asset master, transformer, hierarchy, GIS, canonical IDs, API/audit foundation | Users can view and manage the core asset and location information. |
| **MVP 2 — Event to Incident** | One source integration, raw/normalized events, identity mapping, data quality, alarm and incident | A source event can be traced to the correct asset, alarm and incident. |
| **MVP 3 — Incident to Field** | Work order, dispatch, mobile, safety, inspection, evidence and completion | A dispatcher can send work to a technician and the technician can complete it. |
| **MVP 4 — End-to-End Hardening** | Integration failures, security, performance, audit, synchronization, end-to-end testing and UAT | The complete event-to-resolution scenario passes agreed acceptance testing. |

# 9. Recommended MVP Statement

The MVP will deliver a focused, end-to-end utility asset operations workflow that receives an electrical asset event, identifies and locates the affected asset, creates and manages the alarm and incident, creates and dispatches work, enables field execution and evidence capture, and completes the operational record through restoration, closure and asset history.

**Source basis:** Utility Asset & Field Operations Platform — Business & Product Requirements v1.0, September 2026. This document narrows the existing requirements into an MVP delivery baseline; it does not replace them.
